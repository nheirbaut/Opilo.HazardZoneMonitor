# CRAP Analysis Skill - Executive Summary

## Answers to Your 6 Questions

### 1. ✅ EXACT WORKFLOW IT PRESCRIBES

**Initialization** (one-time):
```bash
# Create coverage config
cat > coverage.runsettings << 'XML'
<?xml version="1.0" encoding="utf-8" ?>
<RunSettings>
  <DataCollectionRunSettings>
    <DataCollectors>
      <DataCollector friendlyName="XPlat code coverage">
        <Configuration>
          <Format>cobertura,opencover</Format>
          <Exclude>[*.Tests]*,[*.Benchmark]*,[*.Migrations]*</Exclude>
          <ExcludeByAttribute>Obsolete,GeneratedCodeAttribute,CompilerGeneratedAttribute,ExcludeFromCodeCoverageAttribute</ExcludeByAttribute>
          <ExcludeByFile>**/obj/**/*,**/*.g.cs,**/*.designer.cs,**/*.razor.g.cs,**/*.razor.css.g.cs,**/Migrations/**/*</ExcludeByFile>
          <IncludeTestAssembly>false</IncludeTestAssembly>
          <SingleHit>false</SingleHit>
          <UseSourceLink>true</UseSourceLink>
          <SkipAutoProps>true</SkipAutoProps>
        </Configuration>
      </DataCollector>
    </DataCollectors>
  </DataCollectionRunSettings>
</RunSettings>
XML

# Install ReportGenerator
dotnet tool install --global dotnet-reportgenerator-globaltool
# OR add to .config/dotnet-tools.json and run: dotnet tool restore
```

**Execution** (per analysis run):
```bash
# Clean, collect, generate, view
rm -rf coverage/ TestResults/

dotnet test tests/MyApp.Tests.Unit \
  --settings coverage.runsettings \
  --collect:"XPlat Code Coverage" \
  --results-directory ./TestResults

dotnet reportgenerator \
  -reports:"TestResults/**/coverage.opencover.xml" \
  -targetdir:"coverage" \
  -reporttypes:"Html;TextSummary;MarkdownSummaryGithub"

# View results
cat coverage/Summary.txt
open coverage/index.html
```

**Key commands**:
| Command | What It Does |
|---------|-------------|
| `dotnet test --settings coverage.runsettings` | Instruments code with coverage collection |
| `--collect:"XPlat Code Coverage"` | Tells .NET to collect coverage (Coverlet is implicit) |
| `--results-directory ./TestResults` | Writes `coverage.opencover.xml` and `coverage.cobertura.xml` |
| `reportgenerator -reports:... -targetdir:... -reporttypes:...` | Transforms XML into HTML/text/markdown reports |

### 2. ✅ HOW IT USES OPENCOVER & REPORTGENERATOR

**OpenCover Format** (`coverage.opencover.xml`):
- XML file generated by Coverlet (XPlat Code Coverage collector)
- **Contains cyclomatic complexity per method** — this is the KEY difference from Cobertura
- Structure:
  ```xml
  <CoverageSession>
    <Modules>
      <Module>
        <Classes>
          <Class>
            <Methods>
              <Method>
                <MethodPoint 
                  vc="5"              <!-- Visit count (execution count) -->
                  p1="3"              <!-- Cyclomatic Complexity! -->
                  p2="0"              <!-- Branch info -->
                  ... />
              </Method>
            </Methods>
          </Class>
        </Classes>
      </Module>
    </Modules>
  </CoverageSession>
  ```

**ReportGenerator Role**:
1. **Input**: Reads `TestResults/**/coverage.opencover.xml`
2. **Processing**: 
   - Extracts complexity (`p1` attribute) + coverage data
   - **Calculates CRAP score** per method: `Complexity × (1 - Coverage)²`
   - Sorts by risk
3. **Output**: 
   - `coverage/index.html` — **Risk Hotspots section** (sorted by CRAP score)
   - `coverage/Summary.txt` — Text summary
   - `coverage/SummaryGithub.md` — PR comment-friendly markdown
   - `coverage/Cobertura.xml` — Merged XML for CI tools

**Why OpenCover is mandatory**:
- Cobertura format does NOT include complexity metrics (`p1` attribute)
- ReportGenerator needs complexity to calculate CRAP
- If you only collect Cobertura, you get coverage but NOT CRAP scores

### 3. ✅ COVERAGE.RUNSETTINGS FILE DETAILS

**Location**: Repository root as `coverage.runsettings`

**The file does TWO things**:

**Thing 1: Controls what gets collected**
```xml
<Format>cobertura,opencover</Format>
```
→ Generates both formats (OpenCover required, Cobertura optional)

**Thing 2: Excludes noise**
```xml
<Exclude>[*.Tests]*,[*.Benchmark]*,[*.Migrations]*</Exclude>
```
→ Don't instrument test/benchmark/migration assemblies (they're not "production code")

```xml
<ExcludeByAttribute>Obsolete,GeneratedCodeAttribute,CompilerGeneratedAttribute,ExcludeFromCodeCoverageAttribute</ExcludeByAttribute>
```
→ Skip generated code, marked obsolete, explicitly opted-out

```xml
<ExcludeByFile>**/obj/**/*,**/*.g.cs,**/*.designer.cs,**/*.razor.g.cs,**/*.razor.css.g.cs,**/Migrations/**/*</ExcludeByFile>
```
→ Skip auto-generated files (source generators, Blazor, EF migrations)

**Optimization flags**:
```xml
<SingleHit>false</SingleHit>          <!-- Count all executions, not just "executed once" -->
<UseSourceLink>true</UseSourceLink>    <!-- Enable GitHub integration for source links -->
<SkipAutoProps>true</SkipAutoProps>    <!-- Don't count auto-property branches (trivial) -->
```

**Full reference**: See `CRAP_REFERENCE_ANALYSIS.md` section 3

### 4. ✅ CRAP FORMULA & EXAMPLES

**Formula**:
```
CRAP Score = Cyclomatic Complexity × (1 - Coverage)²
```

**Real Examples**:

| Method | Complexity | Coverage | Calculation | CRAP | Risk |
|--------|-----------|----------|-------------|------|------|
| `GetUserId()` | 1 | 0% | 1 × (1 - 0)² | **1.0** | ✅ Low |
| `ParseToken()` | 54 | 52% | 54 × (1 - 0.52)² = 54 × 0.23 | **12.4** | ⚠️ Medium |
| `ValidateForm()` | 20 | 0% | 20 × 1 | **20.0** | ⚠️ Medium |
| `ProcessOrder()` | 45 | 20% | 45 × 0.64 | **28.8** | 🔴 High |
| `ImportData()` | 80 | 10% | 80 × 0.81 | **64.8** | 🔴 High |

**Risk Thresholds**:
```
CRAP < 5      → ✅ Low — Well-tested, safe to modify
5 ≤ CRAP ≤ 30 → ⚠️ Medium — Acceptable but watch it
CRAP > 30     → 🔴 High — Needs tests or refactoring
```

**Key Insight**: Coverage has **quadratic impact**:
- 0% → multiplier = 1.0 (full penalty)
- 50% → multiplier = 0.25 (very good)
- 100% → multiplier = 0 (no penalty)

→ Testing complex code pays exponential dividends

### 5. ✅ EDGE CASES & HOW SKILL HANDLES THEM

**Edge Case 1: Complex but well-tested code**
```
OrderProcessor.Calculate()
- Complexity: 28
- Coverage: 85%
- CRAP: 28 × (1 - 0.85)² = 0.63
→ ✅ LOW RISK (complex ≠ risky if tested)
```
**Skill says**: "Complex but covered is safe to modify"

**Edge Case 2: Simple untested code**
```
GetUserId()
- Complexity: 1  
- Coverage: 0%
- CRAP: 1 × 1 = 1.0
→ ✅ LOW RISK (borderline acceptable)
```
**Skill says**: "May not flag but should still test"

**Edge Case 3: Generated code (RecordEventArgs, DTOs)**
```csharp
[ExcludeFromCodeCoverage]
public record PersonAddedEventArgs(Guid Id, string Name);
```
**Solution**: Mark with `[ExcludeFromCodeCoverage]` attribute
**Skill handles**: Via `coverage.runsettings`:
```xml
<ExcludeByAttribute>ExcludeFromCodeCoverageAttribute</ExcludeByAttribute>
```

**Edge Case 4: Auto-generated files (*.g.cs, *.razor.g.cs, EF migrations)**
**Skill handles**: Via:
```xml
<ExcludeByFile>**/*.g.cs,**/*.designer.cs,**/*.razor.g.cs,**/*.razor.css.g.cs,**/Migrations/**/*</ExcludeByFile>
```
→ Automatically excluded, no manual action needed

**Edge Case 5: Auto-properties counted as branches**
```csharp
public string Name { get; set; }  // Don't count as branch!
```
**Skill handles**: Via:
```xml
<SkipAutoProps>true</SkipAutoProps>
```

**Edge Case 6: When to lower coverage thresholds**
- ✅ Legacy codebases being modernized (document in README)
- ✅ Generated code that can't be modified
- ✅ Third-party wrapper code (temporary measure)

- ❌ NEVER: "Too hard to test" → refactor instead
- ❌ NEVER: "We'll add tests later" → add them now
- ❌ NEVER: New features → should meet standards from start

## Key Takeaways

1. **Workflow is linear**: Config → Test → Collect (OpenCover) → Generate (ReportGenerator) → Analyze (Risk Hotspots)
2. **OpenCover is mandatory** because it contains complexity metrics; Cobertura alone won't work
3. **CRAP formula is elegant**: Combines two metrics (complexity + coverage) into one risk score
4. **Edge cases are handled** via exclusion patterns in coverage.runsettings
5. **No auxiliary files** — skill is self-contained in SKILL.md
6. **CI/CD ready**: Complete GitHub Actions + Azure Pipelines examples provided
7. **Coverage has quadratic impact**: 50% coverage is 4× better than 0%, not 2×
